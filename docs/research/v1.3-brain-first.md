# Brain-first README and icon research

Research for Cortex 1.3, asked against primary sources: how a visual developer
tool should present its signature view, and how a desktop app icon survives
small sizes. The product decision that uses this is in
[docs/marketing.md](../marketing.md).

## 1. The README is a first screen, not a manual

GitHub says a README is often the first item a visitor sees and should answer
what the project does, why it is useful, how to start, where to get help and who
maintains it. GitHub also truncates rendered README content beyond 500 KiB, so
the top has to carry the argument and deep detail belongs elsewhere.

- [GitHub Docs — About READMEs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)
- [GitHub Docs — Basic writing and formatting syntax](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)

Repository images should use relative paths, not absolute links. GitHub supports
theme-aware README images through `<picture>` and `prefers-color-scheme`, but
Cortex's screenshots are already dark and the plate is warm, so one image works
in both themes.

- [GitHub Docs — Quickstart for writing on GitHub](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/quickstart-for-writing-on-github)
- [GitHub Blog — dark/light Markdown images](https://github.blog/developer-skills/github/how-to-make-your-images-in-markdown-on-github-adjust-for-dark-mode-and-light-mode/)

The repository social preview is the one surface with an official size:
PNG/JPG/GIF, under 1 MB, at least 640×320, recommended 1280×640. Transparency is
supported but can render inconsistently, so Cortex's card is opaque.

- [GitHub Docs — Customizing your repository's social media preview](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/customizing-your-repositorys-social-media-preview)

GitHub's docs style guide recommends alt text of 40–150 characters that starts
with the graphic type and names the relevant state or highlight.

- [GitHub Docs — Style guide](https://docs.github.com/en/contributing/style-guide-and-content-model/style-guide)

## 2. What visual-first READMEs actually do

Observed conventions, not GitHub policy:

| Project | First screen |
| --- | --- |
| [AFFiNE](https://github.com/toeverything/AFFiNE) | Full-width product hero, wordmark and tagline, badges, a second full-width GIF, then prose. |
| [tldraw](https://github.com/tldraw/tldraw) | Theme-aware `<picture>` hero, badges, a one-line SDK descriptor, then features. |
| [Excalidraw](https://github.com/excalidraw/excalidraw) | Theme-aware cover, tagline, badges, a large showcase screenshot with one caption, then features. |
| [Logseq](https://github.com/logseq/logseq) | Logo, tagline, download CTA and badges; the demo GIF appears later. Recognisable, but less visual-first than the three above. |

The pattern worth copying is: a real product hero, one line of positioning, a
small set of meaningful badges, a real view or short demo, then feature prose
and install instructions. Several projects hotlink CDN images; GitHub's docs
recommend relative repository paths, which is what Cortex does.

## 3. One focal point, real product

Apple's App Store asset guidance is the clearest primary-source statement of
hero composition for a software product:

- aim for strong composition and a clear focal point in each asset;
- focus on a single clear idea; visually dense or cluttered assets dilute it;
- screenshots should show the app in use and lead with the best features;
- the first up to three screenshots can appear in search results;
- a text overlay should be a short phrase that enhances the visual, not a
  description, and key content should sit inside a safe area;
- if the app supports Dark Mode, show at least one dark screenshot.

- [Apple — App Store asset best practices](https://developer.apple.com/app-store/asset-best-practices)
- [Apple — Creating your product page](https://developer.apple.com/app-store/product-page)
- [Apple — App Review guideline 2.3.3](https://developer.apple.com/help/app-review/guideline-reference/2-3-3-screenshots)

For Cortex this means: the Brain view itself, cropped tightly enough that it
reads at roughly 800 px wide, with one cluster/path dominant. No logo-only
banner, no badge wall, no second competing screenshot above the fold. A caption
of one line is enough.

GitHub has no official README hero dimensions or "above the fold" rule. 1280×640
is specifically the social-preview recommendation; a 16:10 in-body screenshot is
a convention.

## 4. App-icon rules that matter here

### Apple Human Interface Guidelines

- A simple icon is easiest to understand and recognise. Find one concept, make
  it the core idea, and express it with a minimal number of shapes.
- Extremely thin line weights and sharp corners lose detail and crispness at
  small sizes. Avoid photos, UI screenshots and text.
- Filled, overlapping shapes with depth work better than hairline diagrams.
- Keep the core visual features consistent across default, dark, clear and
  tinted appearances.
- 1024×1024 is the master for iOS/iPadOS/macOS; the system masks corners and
  scales down.

[Apple HIG — App icons](https://developer.apple.com/design/human-interface-guidelines/app-icons)

### Microsoft Windows icon design

- An icon should represent the app's value proposition in a singular element
  using simple forms; one metaphor is better than two, and a literal metaphor is
  better than an abstract one.
- Use a 48×48 grid, with a distinctive silhouette that stays legible at small
  sizes and as few shapes and corners as possible.
- Use dark, medium and light values; at least half the icon should pass 3.0:1
  contrast on both light and dark themes.
- Ship at least 16, 24, 32, 48 and 256 px. Windows looks for an exact size first
  and scales down otherwise.
- Plated icons may need light/dark variants; unplated target-size variants are
  what the taskbar and Start prefer.

- [Microsoft Learn — Design guidelines for Windows app icons](https://learn.microsoft.com/en-us/windows/apps/design/style/iconography/app-icon-design)
- [Microsoft Learn — Construct your Windows app's icon](https://learn.microsoft.com/en-us/windows/apps/design/style/iconography/app-icon-construction)

### Material icons

- 24 dp baseline, 20 dp live area and 2 dp padding; additional optical sizes at
  20, 40 and 48 dp.
- Simplify for clarity, make icons graphic and bold, keep one visual style and
  avoid delicate organic shapes.
- Product icons should communicate the core idea simply and boldly, with a
  unique silhouette and a clear focal point.

- [Material 3 — Designing icons](https://m3.material.io/styles/icons/designing-icons)
- [Material — Product icons](https://material.io/design/iconography/product-icons.html)

## 5. What this meant for Cortex

The previous mark failed the small-size test for a specific reason: thirteen
overlapping circles made a scalloped "cloud" outline, and two independently
offset spiral strokes collapsed into a fingerprint at 32 px. The replacement:

- draws one solid brain silhouette with four large lobes per hemisphere, a
  wider parietal middle and a smooth base;
- cuts the thinking trail as one ribbon, then restores a narrow centre strip so
  it reads as a double band at 256 px and as a single bright spiral at 16 px;
- uses a 22 px vertical seam at 1024, which survives as a visible split at
  32 px;
- keeps a warm-white plate and near-black ink for contrast on both light and
  dark docks;
- exports 16, 20, 24, 32, 40, 48, 64, 128 and 256 px, plus `.ico`, `.icns`,
  tray glyphs and the window icon from the same geometry.

The Brain view and the icon now use the same metaphor at different scales: a
brain mass, a seam, and a trail through it.

## What could not be verified

- There is no official GitHub README hero dimension or "above the fold" rule;
  1280×640 is the social-preview spec, not an in-body requirement.
- "Avoid generic geometric marks" is a synthesis of Apple's "simple, unique",
  Microsoft's "literal metaphor" and Material's "visually distinct" guidance,
  not a quoted rule.
- There is no single cross-platform app-icon specification. Apple and Microsoft
  are the relevant primary sources for a Windows/macOS desktop app; Material is
  useful for the in-app icon set, not the app icon.
- Cortex has no analytics, so the README/demo response can only be judged from
  GitHub traffic, demo-page visits and release feedback, not A/B tests.
