# v1.2 — hosting the UI in a real window

Research for replacing the Chromium `--app` window (ADR 0004/0005) with an
embedded system webview. Checked against primary sources in November 2026.

## Decision

Use **`wry` + `tao` directly**, not Tauri. Tauri is built on Wry and Tao and
adds config, codegen, IPC, permissions, plugins and a bundler — almost all of
which Cortex already has (an axum server, a hand-written UI, an installer and an
updater). Tauri would also leave `WebviewUrl::External` as the only useful part
of the framework. Sources: [Tauri architecture](https://v2.tauri.app/concept/architecture/),
[`WebviewUrl`](https://docs.rs/tauri/2.12.7/tauri/enum.WebviewUrl.html).

| Concern | Choice |
| --- | --- |
| Window + webview | `wry 0.57`, `tao 0.37` |
| Tray | `tray-icon 0.26` in the same Tao event loop |
| Windows icon | resource compiler at build time (embedded `.ico`) |
| macOS shape | a minimal `.app` bundle with `Info.plist` + `.icns` |
| Linux | stay on the browser path (see below) |

## The three webviews

- **WebView2 (Windows)** is Edge/Chromium. WebGL2 exists where the GPU and
  driver support it; Microsoft calls GPU acceleration critical and Edge is
  deprecating software WebGL fallbacks. Sources: [WebView2 performance](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/performance),
  [SwiftShader policy](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/enableunsafeswiftshader).
- **WKWebView (macOS)** has WebGL2 since Safari 15 / macOS 12 and is Metal
  backed. The system version decides support. Sources: [Safari 15 notes](https://developer.apple.com/documentation/safari-release-notes/safari-15-release-notes),
  [WebKit Safari 15](https://webkit.org/blog/11989/new-webkit-features-in-safari-15).
- **WebKitGTK (Linux)** enabled WebGL2 by default in **2.40**. Wry links
  WebKitGTK 4.1, GTK 3 and libsoup 3 at load time; a missing
  `libwebkit2gtk-4.1.so.0` stops the process before `main`. There is no
  `dlopen` path in Wry. Sources: [WebKitGTK 2.40](https://www.webkitgtk.org/2023/03/17/webkitgtk2.40.0-released.html),
  [Wry crate docs](https://docs.rs/wry/0.57.2/wry/), [`ld.so(8)`](https://man7.org/linux/man-pages/man8/ld.so.8.html).

That last point is why v1.2 keeps Linux on the browser path: shipping the
current self-contained binary matters more than a GTK/WebKit dependency that is
not on every distro.

## Choices that follow from the sources

- **Serve `http://127.0.0.1:PORT`.** Loopback is a secure context, so
  `localStorage`, modules, CSP and WebGL behave as they do in a browser. Wry's
  `with_html` pages get a null origin and custom protocols differ per platform.
  Sources: [Secure Contexts](https://www.w3.org/TR/secure-contexts/),
  [Wry builder](https://docs.rs/wry/0.57.2/wry/struct.WebViewBuilder.html).
- **Give WebView2 a writable data directory.** Wry documents that the default
  fails when the app is installed under `Program Files`. Source:
  [`WebContext`](https://docs.rs/wry/0.57.2/wry/struct.WebContext.html).
- **Keep the localhost origin and guard navigation.** The window may only
  navigate to its own origin; external links go to the user's browser.
- **Windows needs its own icon resource.** The `.ico` embedded in the exe is
  what Explorer, the taskbar and Alt-Tab use. The window builder icon alone is
  not enough. Source: [Microsoft icon construction](https://learn.microsoft.com/en-us/windows/apps/design/style/iconography/app-icon-construction).
- **macOS needs a bundle.** An unbundled binary defaults to the prohibited
  activation policy and lacks an identity, icon and normal signing shape.
  Build `Cortex.app/Contents/{Info.plist,MacOS,Resources}`. Sources:
  [activation policy](https://developer.apple.com/documentation/appkit/nsapplication/activationpolicy-swift.enum/prohibited),
  [bundle structure](https://developer.apple.com/library/content/documentation/CoreFoundation/Conceptual/CFBundles/BundleTypes/BundleTypes.html).
- **Tray icons are not one asset.** macOS uses a template-style image that the
  system recolours; Windows/Linux need artwork that survives both light and
  dark panels. Source: [`NSImage.isTemplate`](https://developer.apple.com/documentation/appkit/nsimage/1520017-istemplate).

## Icon pipeline

One 1024 master in `tools/make-icons.py`, exported to:

- `.ico` with 16, 20, 24, 32, 40, 48, 64, 128 and 256 px (Microsoft documents
  shell sizes up to 256);
- `.icns` with the modern 16/32/64/128/256/512/1024 set;
- PNGs from 16 to 1024 for Linux and documentation;
- white and ink tray glyphs, plus raw RGBA for the window and tray.

`assets/icons/cortex.ico` is embedded in the exe and used by the installer;
`assets/icons/cortex.icns` goes into the macOS bundle. The in-app mark is
`web/logo.svg`, drawn from the same geometry as the raster assets.

Small-size guidance comes from Microsoft's icon grid and Apple's advice to
simplify small artwork rather than only downscale it.

## What this does not solve

- WebView2 runtime absence. wry reports an error; `cortex app` then falls back
  to the browser and says so in the log. The installer does not yet bootstrap
  the runtime.
- Notarization. The macOS bundle is ad-hoc signed, so Gatekeeper still asks for
  a downloaded copy until a Developer ID certificate is available.
- Linux native windows. A future release can gate a WebKitGTK build behind a
  package dependency; v1.2 deliberately does not.
